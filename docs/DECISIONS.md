# 决策记录（ADR-lite）

> 状态：当前。每条只记「决定了什么 / 为什么 / 什么时候可能推翻」。新决策追加在末尾，不改旧条目。

## D-001 识别放在浏览器（Chrome Web Speech），不在本机跑 ASR 模型

**日期**：2026-11-02
**决定**：单机版沿用参考项目的主链路 —— Chrome/Edge 内置 `webkitSpeechRecognition` 识别，
本机服务只接收文字。
**理由**：与服务器版逻辑一致；不需要下载/维护 sherpa-onnx 模型；CPU 占用低，不会和 OBS
编码抢资源；参考项目的切句参数就是为这条链路调过的。
**代价**：只支持 Chrome/Edge；识别本身依赖 Google 在线服务；非 Chrome 不可用。
**何时推翻**：用户要求完全离线，或非 Chrome 环境成为常态 → M5 接 sherpa-onnx。

## D-002 单进程、无数据库、无账号

**日期**：2026-11-02
**决定**：一个 FastAPI 进程 + 内存状态；不建库，不做用户体系。
**理由**：只在本机给自己用，并发为 1；数据库与账号是服务器版的业务需要，这里全是负担。
**代价**：重启后不保留历史字幕；不能多人同时用。
**何时推翻**：需要「保存上一场字幕」→ 写 JSONL/SRT 文件即可，仍不需要数据库。

## D-003 只监听 127.0.0.1，不做鉴权

**日期**：2026-11-02
**决定**：绑定 loopback，不校验 Host/Origin，不做 view token。
**理由**：本机单人使用；参考项目的 token/Host 校验是为了公网防滥用。
**代价**：同一台机器的其他本地程序理论上可以连；不构成实际风险。
**何时推翻**：要做局域网给第二台机器看 → 那时必须加 token 与 Host 校验。

## D-007 交付形态：PyInstaller 单文件 exe（带控制台窗口）

**日期**：2026-11-02
**决定**：用 `build_exe.bat` 打 `dist\LiveSubLocal.exe`（`--onefile --console`），
用户拷到任意文件夹双击即可；首次运行在 exe 旁边生成 `config.toml` / `api.toml`。
**理由**：用户要的是「一个 exe 双击 → 自动开浏览器」，不能要求装 Python。
控制台窗口保留，用来显示地址、错误和 Ctrl+C 停止。
**代价**：单文件启动要解压（约 1–2 秒）；exe 约 16 MB；exe 必须放在可写目录。
**何时推翻**：需要托盘图标/无窗口启动，或改用安装包（Inno Setup）。

## D-008 打包加 `--runtime-tmpdir .`

**日期**：2026-11-02
**决定**：exe 解压到自身所在目录，而不是系统 Temp。
**理由**：少数机器上系统 Temp 被安全软件/组策略锁住，单文件 exe 会报
`Could not create temporary directory` 直接退出；解压到自身目录可以绕开。
**代价**：exe 所在目录必须可写（不能放 `C:\Program Files`）；运行时会短暂出现 `_MEIxxxx` 目录。
**何时推翻**：改成 onedir 分发，或用户环境确认 Temp 正常。

**日期**：2026-11-02
**决定**：`/studio` 全日语，不做语言切换；识别固定 `ja`、译文固定 `zh`，界面上直接显示

## D-012 字幕样式在控制台里改，实时下发并持久化到 settings.json

**日期**：2026-11-02
**决定**：样式不再只读 `config.toml`：控制台改一项 → `POST /api/display` → 服务端合并校验 →
写 `settings.json` → 把带 `display` 的最新快照推给所有 viewer。`/view` 从每条消息里取样式，
不刷新即可生效。
**理由**：OBS 里刷新浏览器源很麻烦；参考项目也是「样式随快照下发」。
**代价**：多一个用户文件 `settings.json`；`config.toml` 的 `[display]` 只作为初始值。
**何时推翻**：需要多套主题切换时，改成主题列表 + 当前主题 ID。

## D-015 Windows 打开浏览器用 `rundll32 url.dll,FileProtocolHandler`

**日期**：2026-11-02
**决定**：启动后先探测端口就绪，再依次尝试
`rundll32.exe url.dll,FileProtocolHandler <url>` → `os.startfile` → `cmd /c start`，
并把实际用到的方式打印到控制台。
**理由**：用户反馈 exe 双击后浏览器没弹出来；参考同机的 `D:\哔哩哔哩OBS礼物特效`
（`src/server/index.mjs` 的 `openPanel()`）用的是 `execFile('rundll32.exe',
['url.dll,FileProtocolHandler', url])`，走的是和资源管理器双击链接相同的 ShellExecute 路径，
比 Python 的 `webbrowser`（会先读 `BROWSER` 环境变量）可靠。
**代价**：`rundll32` 只要进程能起就算成功，无法确认浏览器真的弹了；失败时只能靠控制台提示。
**何时推翻**：改用托盘程序或 Electron 外壳时，直接用宿主 API 打开页面。

## D-016 电平表默认开启，并加「発話しきい値」滑块

**日期**：2026-11-02
**决定**：`/studio` 打开即调用 `getUserMedia` 开启电平表（不再需要先点按钮）；新增阈值滑块
（-60〜-10 dBFS，默认 -40），在电平表上画一条竖线，音量超过就显示「発話中」、低于显示「無音」；
阈值存 `localStorage`。
**理由**：参考项目的「入力レベルと認識しきい値」就是这一块；用户要求默认就能看到音量。
**代价**：打开控制台会立刻弹出麦克风权限请求；**阈值只是表上的参考线，不改变 Chrome 的识别时机**
（Chrome 内部 VAD 无法从网页调整）。这一点在界面提示和 README 里都写明了。
**何时推翻**：接入本地 ASR（sherpa-onnx）后，阈值可以真正参与 VAD 起止判断。

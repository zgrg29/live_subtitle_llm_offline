# 决策记录（ADR-lite）

## D-001 识别放在浏览器（Chrome Web Speech），不在本机跑 ASR 模型

**日期**：2026-11-02
**决定**：单机版沿用参考项目的主链路 —— Chrome/Edge 内置 `webkitSpeechRecognition` 识别，
本机服务只接收文字。
**理由**：与服务器版逻辑一致；不需要下载/维护 sherpa-onnx 模型；CPU 占用低，不会和 OBS
编码抢资源；参考项目的切句参数就是为这条链路调过的。
**代价**：只支持 Chrome/Edge；识别本身依赖 Google 在线服务；非 Chrome 不可用。
**何时推翻**：用户要求完全离线，或非 Chrome 环境成为常态 → M5 接 sherpa-onnx。

## D-002 单进程、无数据库、无账号

**日期**：2026-11-02
**决定**：一个 FastAPI 进程 + 内存状态；不建库，不做用户体系。
**理由**：只在本机给自己用，并发为 1；数据库与账号是服务器版的业务需要，这里全是负担。
**代价**：重启后不保留历史字幕；不能多人同时用。
**何时推翻**：需要「保存上一场字幕」→ 写 JSONL/SRT 文件即可，仍不需要数据库。

## D-003 只监听 127.0.0.1，不做鉴权

**日期**：2026-11-02
**决定**：绑定 loopback，不校验 Host/Origin，不做 view token。
**理由**：本机单人使用；参考项目的 token/Host 校验是为了公网防滥用。
**代价**：同一台机器的其他本地程序理论上可以连；不构成实际风险。
**何时推翻**：要做局域网给第二台机器看 → 那时必须加 token 与 Host 校验。

## D-004 包放在仓库根目录（不用 src/ 布局）

**日期**：2026-11-02
**决定**：`livesub_local/` 直接在根目录，`run.py` 直接 import，不需要 `pip install -e .`
或设置 `PYTHONPATH`。
**理由**：双击 `start.bat` 就要能跑，少一层路径配置；项目规模不需要打包发布。
**代价**：以后要发布到 PyPI 需要改成 src 布局。
**何时推翻**：需要 pip 安装或打包 exe 时。

## D-005 提交用 GitHub Desktop 自带的 git，且只本地提交、不 push

**日期**：2026-11-02
**决定**：`%LOCALAPPDATA%\GitHubDesktop\app-3.6.7\resources\app\git\cmd\git.exe`
（本机没装独立 git）。每场结束提交一次，不 push。
**理由**：用户指定的提交方式；本地提交足够留痕，远端推送由用户自己决定。
**代价**：GitHub Desktop 升级后版本号路径会变，需要在 AGENTS.md 里更新。
**何时推翻**：用户装了独立 git，或要求推到 GitHub。

## D-007 交付形态：PyInstaller 单文件 exe（带控制台窗口）

**日期**：2026-11-02
**决定**：用 `build_exe.bat` 打 `dist\LiveSubLocal.exe`（`--onefile --console`），
用户拷到任意文件夹双击即可；首次运行在 exe 旁边生成 `config.toml` / `api.toml`。
**理由**：用户要的是「一个 exe 双击 → 自动开浏览器」，不能要求装 Python。
控制台窗口保留，用来显示地址、错误和 Ctrl+C 停止。
**代价**：单文件启动要解压（约 1–2 秒）；exe 约 16 MB；exe 必须放在可写目录。
**何时推翻**：需要托盘图标/无窗口启动，或改用安装包（Inno Setup）。

## D-008 打包加 `--runtime-tmpdir .`

**日期**：2026-11-02
**决定**：exe 解压到自身所在目录，而不是系统 Temp。
**理由**：少数机器上系统 Temp 被安全软件/组策略锁住，单文件 exe 会报
`Could not create temporary directory` 直接退出；解压到自身目录可以绕开。
**代价**：exe 所在目录必须可写（不能放 `C:\Program Files`）；运行时会短暂出现 `_MEIxxxx` 目录。
**何时推翻**：改成 onedir 分发，或用户环境确认 Temp 正常。

## D-009 控制台界面只做日语，翻译方向固定 日本語 → 中文

**日期**：2026-11-02
**决定**：`/studio` 全日语，不做语言切换；识别固定 `ja`、译文固定 `zh`，界面上直接显示
「日本語 → 中文」。`config.toml` 里的 `source_language` / `target_languages` 只作为服务端默认值保留。
**理由**：目标使用者是日本主播；多语言切换在单机版里只会增加出错面。
**代价**：想改方向要改代码里的两个常量（`studio.html` 的 `SOURCE_LANG` / `TARGET_LANG`）。
**何时推翻**：需要给中文/英文主播用时再加回来。

## D-010 把参考项目首页的「OBS 自定义 CSS 提示词」搬进控制台

**日期**：2026-11-02
**决定**：控制台底部加一栏「OBS 字幕の見た目を変える（AI 用プロンプト）」，
内容改写成本页真实 DOM（`#stage` / `.pair` / `.source` / `.target`）与真实 CSS 变量
（`--target-size` / `--source-size` / `--outline` / `--fade` / `--gap`），带一键复制。
**理由**：参考项目把它放在公开首页（服务器版要给访客看）；单机版没有首页，控制台才是用户唯一入口。
**代价**：提示词与页面结构耦合，改 DOM 时要同步改提示词（已写进本文件与 ARCHITECTURE）。
**何时推翻**：M2 做主题预设后，提示词改为「在预设基础上改」。
